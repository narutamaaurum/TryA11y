# Architecture

## Package graph

```
packages/
├── core/       @trya11y/core      — engine (no DOM dependency at import time)
├── extension/  @trya11y/extension — Chrome MV3 (depends on @trya11y/core)
└── web/        @trya11y/web       — docs/landing site (depends on @trya11y/core)
```

`core` has no runtime dependency on either `extension` or `web`. Both consumers depend on `core`.

The service worker in the extension imports from `@trya11y/core/worker` — a DOM-free subpath that excludes `scanner.ts` and `patcher.ts` (which reference browser globals). This prevents bundler errors when the service worker bundle is evaluated in an environment without `document`.

## Scan → fix → patch pipeline

```
axe.run(context)              scanner.ts
       ↓
 ScanResult / A11yIssue[]     types.ts
       ↓
 generateFixes(issues, doc)   fixer.ts    — heuristic registry lookup
       ↓
 enhanceFixes(issues, fixes)  llm.ts      — optional Ollama pass (low/medium confidence only)
       ↓
 applyPatches(ops)            patcher.ts  — clones elements, never mutates live DOM directly
       ↓
 generateReport(result)       reporter.ts — HTML / JSON / Markdown
```

`generateFix` looks up a rule id in the heuristic registry. If no heuristic is registered it falls through to `genericFix`, which returns a low-confidence placeholder so the diff view always has something to show.

`enhanceFixes` only sends issues to Ollama that have `confidence: 'low' | 'medium'` — high-confidence heuristic fixes are not re-generated by the LLM.

## Chrome extension communication

```
                  chrome.tabs.sendMessage
 content script ←────────────────────────── service worker
       |                                          ↑
  axe.run() on                          chrome.runtime.connect
  inspected page                        (Port: 'explain-issue')
       |                                          |
       └──── scan results ──────────────►  DevTools panel (React)
                                                  |
                                          Ollama /api/chat
                                          (streamed via Port)
```

**Why Ports instead of `sendMessage` for Ollama:** Chrome MV3 closes message channels after 30 seconds. Ollama with a 3B model can take longer. A persistent `chrome.runtime.Port` connection keeps the channel alive for the full explanation stream.

**Content script role:** Injects `axe-core` into the inspected page (via `chrome.scripting.executeScript`), runs the scan in the page's JavaScript context, and returns results. It also applies/reverts DOM patches and renders the focus-order overlay.

**Service worker role:** Orchestrates scans, persists settings and history to `chrome.storage.local`, updates the badge, and proxies Ollama calls (the DevTools panel can't call `localhost:11434` directly due to CORS — the service worker makes the request and streams results back via the Port).

## Web docs site

The `web` package is a single-route React + Vite SPA deployed to GitHub Pages. It has no backend. It renders static mockups of the extension UI to show visitors what the tool looks like before they install it.

`VITE_BASE_URL` controls the Vite `base` path so asset URLs work under the `/TryA11y/` GitHub Pages subdirectory.

## Key design decisions

| Decision | Reason |
|---|---|
| `axe.reset()` before every `axe.run()` | axe-core caches internal rule state between runs; without reset, re-scanning the same document after patching returns the same result set even if violations were resolved. |
| Preview `<div>` rendered at `position: fixed; top: -10000px` (not `display: none`) | axe-core's colour contrast and layout rules require elements to be painted and measurable. A hidden container returns 0 violations even if the HTML has real issues. |
| Heuristics clone elements before mutation | `fixer.ts` helpers (`setAttrHtml`, `changeTagHtml`, etc.) return new `outerHTML` strings rather than modifying the live DOM. This makes heuristics deterministic and testable in jsdom without side effects. |
| `@trya11y/core/worker` subpath | Splitting the DOM-dependent modules into a separate export lets the MV3 service worker bundle without `document is not defined` errors at import time, while still sharing types and pure logic with the content script. |
| Ollama timeout 180 s | `llama3.2` (3B) on consumer hardware can take 60–120 s. The 30 s default would silently abort explanations mid-sentence. |
